# v0.3.0 rewrite — final report

Branch `mit-rewrite`, starting from commit 83d9ee4 (tagged locally as
`v0.2.1-gpl-final`). Every commit is authored by Denis Demin.

## Fixture parity

See docs/parity.md. Pearson / Spearman / Kendall agree with R to ≤ 5.6e-16 (r)
and ≤ 2.2e-12 relative (p) on all ten datasets, including missing values under
pairwise-complete handling. Beta functions: ≤ 5.7e-14 relative (cdf/pdf),
≤ 9.2e-15 (quantile). **bicor and hellcor parity is pending**: WGCNA and HellCor
were not installable in the build environment, so their fixtures must be
generated by the owner (`Rscript tools/make_fixtures.R`); the parity tests then
run automatically. Python: matches numpy.corrcoef and scipy.stats
spearmanr/kendalltau (r ≤ 1e-13, p ≤ 1e-9 relative).

## Benchmarks

See docs/benchmarks.md (2-vCPU Xeon vs the old 16-thread 7950X3D figures).
Hellcor 2950 × 77: 102.9 s on 2 threads vs 1575 s on 16 threads (≈ 122× in
thread-seconds; target ≥ 50× met). Kendall ≈ 33×, Pearson/Spearman ≈ 21–23×,
bicor ≈ 9× in thread-seconds. CLI: 10 000 × 10 000 Pearson to .tsv.gz with 89 MB
peak RSS.

## Remaining differences vs R

- Hellcor: default order-selection criterion follows the paper (MISE,
  Appendix C); the rewrite specification described a normalised variant, also
  available (`HellcorCriterion::NormalizedLoo`). Which one matches HellCor is
  unknown until fixtures exist.
- bicor `maxPOutliers < 1`: written from documentation only; unverified.
- Monte-Carlo p-values differ from v0.2 (new random streams), by design.

## Deviations from the specification

1. `full()` is implemented directly (triangle + mirror) rather than on top of
   `full_blocks()`; streaming computes complete rows, so it evaluates symmetric
   pairs twice. Both share the same engine and layout executor. The CLI keeps
   the triangle trick for pairwise methods while the matrix fits in
   `--memory-limit-gb`.
2. Hellcor nearest neighbours are brute force for all n (no uniform grid yet);
   fine for the target regime (n ≲ 2000), parked in docs/ideas.md.
3. Kendall bitsets are used for n ≤ 128 only (memory bound); larger n uses
   Knight's algorithm (2000 × 600: 33 s on 2 threads).
4. `rand` is not a dependency; `rand_chacha` (+ its `rand_core`) is used
   directly with an own unbiased bounded-integer routine.
5. Python requires ≥ 3.9 (abi3-py39) instead of 3.8.
6. Function-length cap is enforced with clippy `too_many_lines` (threshold 60)
   rather than a script; the size script checks file lengths.
7. MSRV is declared as 1.85 (edition 2024) and tested in CI; it could not be
   verified locally (toolchain download blocked).
8. `cargo deny` runs in CI; locally the dependency licences were checked from
   `cargo metadata` (all MIT/Apache/BSD/ISC/Zlib/Unicode options available).
9. The `GTEx_test.sh` script moved to `tools/` and was fixed (package name,
   heredoc arguments, `--legacy-tar` naming) rather than replaced; CLI behaviour
   is covered by `crates/cli/tests/cli.rs`.
